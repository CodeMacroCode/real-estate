The core principle of the system is: CRM = Master Database / Single Source of Truth.
2. SYSTEM ARCHITECTURE
Recommended architecture: Admin/CRM Panel -> CRM Backend/API -> Central Database -> Website API -> 
Public Website.
Additional integration flows: Website Enquiry -> CRM Lead API; CRM Property -> Website Publishing API; CRM 
Status Change -> Website Update/Unpublish; CRM -> WhatsApp/Email/SMS/Notifications; CRM -> Third-party 
Property Portals.
3. SINGLE SOURCE OF TRUTH
The CRM database is the authoritative database for properties, projects, owners, clients, leads, staff, site visits, 
follow-ups, sales transactions, rental transactions and website-managed property information.
Example: a new property is created in CRM with Publish on Website = YES. It becomes available on the public 
website. Price, rent, description and availability changes are propagated to the website. Sold, Leased, Rented or
 
Not Available status removes the property from active website listings while retaining its historical CRM 
record.

7. WEBSITE ENQUIRY -> CRM
Every website enquiry must be automatically captured in the CRM.
Flow: Website property page -> Enquire Now -> form submission -> Website -> CRM Lead API -> create/update 
lead -> assign sales employee -> notify employee/manager.
Duplicate prevention: search by mobile, email and WhatsApp number. If a match exists, update the existing 
lead and append the new enquiry activity; otherwise create a new lead.

35. PROPERTY PUBLISHING SYSTEM
Each property must include Publish on Website = YES/NO.
Publication conditions can require Publish = YES, Status = Active/Available and required public fields 
completed.
A property must be removed from active website listings when Publish = NO, or when Sold, Leased, Rented, 
Blocked, Not Available or Archived, subject to configured business rules.
36. PROPERTY STATUS AUTOMATION
Example: Available -> Sold. The system changes the CRM status, removes the property from active website 
listings, retains the CRM history, updates related deal/pipeline records, writes an activity log and records the 
status change date. Apply equivalent logic to Available -> Leased/Rented and other configured statuses.
